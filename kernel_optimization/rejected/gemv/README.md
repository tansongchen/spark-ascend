# BF16 GEMV / MLP 实验

本轮没有达到可集成的性能收益。保持原始融合 kernel 和运行时适配器不变；所有实验均为 BF16，物理 NPU 4，未使用 NPU 0。

阶段插桩显示，滑窗融合层中 up/GELU、down、QKV 分别约占 49%、23%、15%（包含阶段同步等待）。因此本轮先检查 MLP tile 与搬运粒度。

| 候选 | 改动 | 结果 |
| --- | --- | --- |
| up16 | W1 tile 从 M8 改 M16，单次 DMA 从 40 KiB 改 80 KiB；每次 VF 写两个 padded M8 输出组 | CPU 参考通过；旧微测稍慢，未集成 |
| down2 | W2 tile 从 M4 改 M2，DMA 从 80 KiB 改 40 KiB | CPU 参考通过；旧微测稍慢，未集成 |
| up_pair | 保持 M8 和每核 45/46 tile 分工，将相邻两个 M8 合成一次 80 KiB DMA；逐次执行原 GEMV8 | 严格复测差异不足 1%，未集成 |

up_pair 的 ABI 和权重打包均与基线一致：QKV/O/up/down tile 分别为 8/8/8/4。O→up 的首块预取同步改成两个 M8；末尾奇数 tile 只搬运一个，避免跨界。双缓冲的 MTE2→V、V→MTE2 事件按两个 tile 的生命周期配对。

修正后的同卡 AB/BA 测量：3000 次预热，10 轮交替顺序，每组 5000 次执行。固定输入重复单层不能代表完整模型加速。

| 层与长度 | 基线 μs | up_pair μs | 耗时下降 |
| --- | ---: | ---: | ---: |
| 滑窗 layer 0，32769 | 163.8411 | 163.7903 | 0.031% |
| 全局 layer 3，32769 | 229.8233 | 229.5639 | 0.113% |

两组的 O、MLP 中间值、down、resmid、最终输出和残差均与基线逐位一致；CPU 参考与输出 guard 全部通过。额外 layer 0、长度 513、重复三次的分页边界检查也通过。活跃设备采样均为 1650 MHz，温度 60–68°C。

计时方法已从 v1 修正为 v2：`start.record()` 后立即 `current_stream.synchronize()`，再提交原生 ctypes kernel，保证 Torch 异步任务队列中的起始事件先进入设备流。旧 up16/down2 JSON 原样保留，但未刷新事件队列，不能用作严格加速证据；后续 up_pair 的正式复测使用修正后的顺序。

合并 DMA 没有减少权重字节数，结果说明单纯减少这段 DMA 调用次数没有带来明显收益。独立纯搬运探针的相近吞吐可作为下一轮分析线索，不能据此宣称达到 HBM 硬件上限。本轮停止扩大参数扫描。
